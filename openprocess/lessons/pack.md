# Introduction to process mining

Twelve short lessons, from "what is an event log?" to checking a model
against what really happened. No background is needed: every word is
explained when it first appears, and every lesson is about the same small
example, the orders of a pizza shop.

Each lesson is a few lines of explanation followed straight away by a
question. Answer in the box and press **Check**. Stuck? **Hint** gives a
nudge and **Show answer** explains the answer. The log or the model the
lesson is about is open on the right, so you can look, click and try things
while you think.

Do them in order: each lesson uses the one before. A lesson takes five to
ten minutes. Your answers are saved as you go, so you can stop anywhere.

| | Lesson | You will be able to |
|---|---|---|
| 1 | What is an event log? | read a log: cases, events, activities, variants |
| 2 | What follows what? | read the arrows of a process map and a footprint |
| 3 | The token game | play a Petri net: places, transitions, tokens |
| 4 | Choice and parallel | tell "one of these" from "both, in any order" |
| 5 | When a model is broken | find a deadlock and repair the model |
| 6 | From log to model | see how an algorithm reads a model off a log |
| 7 | Cutting a log into pieces | follow the Inductive Miner step by step |
| 8 | Your first analysis | build a workflow: a log, a miner, a check |
| 9 | Does reality follow the model? | replay a log and count what goes wrong |
| 10 | Alignments | say exactly where a case left the model |
| 11 | What makes a model good? | weigh fitness against precision |
| 12 | Rules | describe a process by what must always hold |
